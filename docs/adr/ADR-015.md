# ADR-015 — Local sessions pair explicitly, pin keys, seal every frame, and stay out of CoreLocal

Status: accepted 2026-09-30 (LAB-019-A).

## Decision

A live session between the lab's devices uses `PeerSession`, one transport-independent layer in `Packages/LabFeatures`, and later experiments (Watch relay, Wi-Fi Aware, Apple TV stages, accessories) reuse it by declaring a `SessionVocabulary` and, where needed, a transport.

- **Identity.** Each device holds an app-generated Curve25519 signing key. Its peer ID is derived from the public key. A name is only a label.
- **Pairing.** A joiner commits to its ephemeral key-agreement key before the host reveals its own, then both derive a six-digit code from the handshake transcript. The host's person reads the code, the joiner's person types it, and the host's person allows the device only after the joiner says it matched. Both sides then pin each other's key and the joiner's role. A host accepts pairing only while a person has opened it, for two minutes and three attempts.
- **Resuming.** A pinned peer rejoins with signatures over a fresh transcript and no code. A peer the host never paired, or paired for another role, is refused before any session data. A host whose key is not the pinned one is refused by the joiner.
- **Sealing.** Every message after the handshake is a protocol-v1 `SessionEnvelope` sealed with ChaCha20-Poly1305 under per-direction keys derived from an ephemeral X25519 agreement and the transcript. A frame that fails authentication closes the link.
- **Forgetting.** Forget ends a pairing at once: the pin, the links, and every request the peer has held are withdrawn together, and nothing sent under that pairing is admitted or allowed again, even after the device pairs anew. A host that commits a held request elsewhere allows it through `Conductor.settle`, which refuses it unless its peer is still paired (fixed after LAB-019-B).
- **Authority.** A peer is the `authorizedPeer` adapter (ADR-011). Messages are data: typed, bounded, strictly decoded, never code, paths, or command lines. A peer's change to stored state is held until the conductor's person allows it, then committed through `OperationService` with a grant for exactly that operation (ADR-013).
- **Profiles.** The session layer and the single-device simulation are in CoreLocal. The Network framework adapter (`PeerSessionNetwork`) and the local network declarations (`NSLocalNetworkUsageDescription`, `NSBonjourServices`, and the Mac sandbox's `network.client` and `network.server`) are only in Companions builds: the Apple TV host and the `LabMacCompanions` and `LabPhoneCompanions` host variants, each with its own scheme.

## Rationale and consequences

CryptoKit offers no password-authenticated key exchange, and a code used as a MAC key could be recovered offline by a device in the middle. A commitment followed by a short code derived from both sides' keys limits such a device to one chance in a million per attempt without any key being secret, as numeric comparison does in Bluetooth pairing. The price is that both people must act: one types, the other allows.

Sealing in the session layer, rather than relying on TLS in one transport, makes the loopback carry exactly the bytes a network carries, so the declared fallback exercises the real protocol, and later transports inherit authentication.

Keeping the adapter out of CoreLocal keeps that profile free of network entitlements, a network framework, and a permission prompt. It costs two more host variants to build, and a person who wants the live path installs a Companions build. Pins live in memory, so a relaunch means pairing again; a host that wants lasting pairings supplies its own trust store, such as one in the keychain.

## Validation

`PeerSessionTests` (handshake, wire, measurement, and session suites), `PeerSessionNetworkTests` (the Network framework over loopback TCP, including envelope-for-envelope equality with the in-process loopback), `LocalConstellationTests`, and the hosted `ConstellationHostTests`. The release manifest checks that CoreLocal links no Network framework and carries no network entitlement.
