# ADR-016 — Focus predicates evaluate notification filter criteria

Status: accepted 2026-10-02 (LAB-013-B).

## Decision

The lab's Focus context evaluates `SELF IN` the allowed lab identifiers, against the notification content's `filterCriteria` string. The SystemSurfaces reminder sets that string to its existing lab notification identifier. Foreign identifiers are still removed before constructing the predicate, and an empty selection admits nothing.

## Rationale and consequences

During Speech Timeline qualification, iOS simulator crashes attributed to the active speech test actually trapped in `LabFocusFilterIntent.appContext`. The previous `request.identifier` key path describes a notification request, but Focus evaluates a string. AppIntents traps while constructing the context with that unsupported expression, including when the system reads intent metadata during app launch.

Apple's [Focus-filter example](https://developer.apple.com/documentation/appintents/defining-your-app-s-focus-filter) and [WWDC22 session](https://developer.apple.com/videos/play/wwdc2022/10121/) use `SELF` and `UNNotificationContent.filterCriteria`. This corrects the existing adapter contract; it adds no permissions, new notification routes, or external services. The minimal shared correction is needed for the Speech Timeline host test to run reliably.

## Validation

The package regression and `SpeechTimelinePhoneTests.theLaunchFocusContextCanBeReadWithoutTrapping` construct the real AppIntents context and evaluate an allowed, foreign, and empty selection. Actual commands and repeated simulator results are recorded in [LAB-013-B](../../tickets/LAB-013-B.md). Notification delivery and a person enabling the Focus filter remain unverified.
