# Assets, model weights, and provenance

Public fixtures must be original or have an explicit redistribution license. Use fictional collections, synthetic receipts, original recordings, procedural geometry, and deliberately public-safe room examples. Never turn a user's imported file, private recording, room scan, health sample, community submission, or employer material into a test fixture by convenience.

Maintain an asset inventory with source, creator, license, allowed redistribution, modification history, and checksum. Source code licensing does not automatically cover every image, font, sound, model, or dataset.

Use system fonts through platform APIs; do not redistribute font files from the build machine. Use system symbols in accordance with their platform terms. Do not bundle Apple marketing art, ripped game assets, ROMs, BIOS images, copyrighted boot screens, or third-party celebrity/character likenesses as a shortcut to a striking demo.

Optional downloaded model weights need an explicit user action, license review, memory estimate, size display, checksum where available, and a removal path. Never silently download gigabytes during first run. The model package and its license remain separate from the MIT-licensed lab source.

A custom audio-recognition fixture should use a few original recordings with different mixes and deliberate negative examples. A video fixture should include original captions and clearly defined rights. Spatial examples should use generated rooms or an explicitly approved capture with identifying details removed.

Publication-safe export is a separate operation from ordinary save. Strip or review embedded location/device metadata, filenames, hidden notes, and source URLs. A pretty screenshot can still contain private information.
