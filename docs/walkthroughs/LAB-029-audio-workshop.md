# Audio Workshop

LAB-029 remains `implemented`. Qualification runs the real AVAudioEngine in offline manual rendering and the audio unit registered in-process. A configuration-change event is injected. These runs open no audio device and do not prove physical route recovery, realtime deadlines, a hardware MIDI source, or loading the AUv3 extension in another host. The iPhone result is a simulator replay of session calls, not a touch or accessibility pass.

Open Audio Workshop from its catalog page. On Mac it also has a sidebar destination and View › Audio Workshop (⌃⌘3). Start with the original Pulse loop, then choose Chords or Noise and Thump. Inspect the graph while changing Gain, Low-pass filter, Cutoff, and Resonance. No sound is recorded or downloaded; all three loops are synthesized by the repository's C kernel.

Play is the explicit action that opens live output. Stop ends it. Panic Mute fades live output to silence; Unmute clears it. Bypass skips the filter and gain, but still respects live mute. Mac shortcuts are ⇧⌘P for Play/Stop, ⇧⌘M for Mute/Unmute, and ⇧⌘B for Bypass. The phone page pins these safety controls below its form. Actual speaker playback was not qualified here.

For a device-free interaction, leave playback stopped and use Send 0, Send 64, and Send 127 in MIDI. The on-screen controller sends MIDI bytes through the same parser and mapping as the input adapter. CC 74 is the default cutoff mapping. Listen to MIDI Sources explicitly opens Core MIDI; this qualification never enables it.

Choose Render the Loop Offline. It produces a float WAVE file at 48 kHz with a SHA-256 summary. Export WAVE File… lets you choose a destination. Process a WAVE File… processes a selected mono or stereo WAVE through the same kernel. Qualification writes its own synthesized file directly and calls the session: system file dialogs and exports have not been driven. Invalid input retains the last usable result. Cancel stops bounded work. Offline processing uses graph parameters and bypass; **live Panic Mute does not silence an offline export**.

Name and Save Preset to commit an item with an app-UI receipt. Presets are user data in Audio Workshop Presets. Loading restores graph and MIDI settings without changing live mute or bypass. Repeating the same operation request returns its original receipt; pressing Save again after success is a new save. Reset Workshop stops playback and clears the experiment's transient graph, log, render, and plugin. Saved presets stay. Global Reset Demo also keeps those user items and selected source-file bytes.

Load the Audio Unit, then Save State and Reload Plugin. This tests the app's in-process audio unit: it saves binary property-list state, creates a new instance, and restores the preset. It is **not** an AUv3 extension discovery or third-party-host test. The isolated extension belongs to LabPhone-Surfaces; CoreLocal embeds no extension, and the Mac has no AUv3 extension target.

The publication inputs are original synthesized audio, neutral preset names, and a deliberate invalid file containing `not audio`. No private media, accounts, device identifiers, screenshots, recordings, or exported audio are included. Structured evidence is in [evidence/LAB-029](../../evidence/LAB-029/). A physical iPhone/iPad run needs its owner and remains not-run.

Accessibility review: native labeled controls, spoken slider values, combined graph summaries, an accessibility-size vertical safety layout, and a save announcement exist in source. Hosted Mac tests exercise Panic Mute and Play through accessibility press actions. Manual VoiceOver, Voice Control, Full Keyboard Access, contrast, large-text layout, and iPad review remain not-run. Render/error/plugin outcomes lack an explicit announcement; live-state changes and cancellation focus need a manual review. The render-stat explanation overstates clang coverage: Swift trampolines are outside its C check, and the 26-family compiler builds unchecked.
